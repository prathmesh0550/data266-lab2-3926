# Part 1: Multimodal RAG for Economics Documents

This part builds a multimodal retrieval-augmented generation system for
question answering over three economics PDF documents.

The system retrieves trusted text, figures, and tables, then uses a
vision-language model to generate a structured answer with citations and
figure/table references.

## Agents and components

The system includes:

- PDF ingestion and text extraction
- Figure and table extraction
- Text chunking and metadata creation
- Dense text retrieval
- BM25 keyword retrieval
- Figure/table caption retrieval
- Image retrieval
- Hybrid retrieval and reciprocal-rank fusion
- Vision-language answer generation
- JSON parsing and answer validation
- Conversation memory with temporary session values
- Submission generation and validation

The answer generator receives only trusted retrieved evidence. Low-trust
content is filtered before answer generation.

The Chroma database has the persistent vector indexes used by the
retriever. The extracted figures and tables are stored separately from the
compact copies used during image-based answering.

## Evaluation
The notebook evaluates:
- Answer correctness on the 25-question golden set
- Status correctness
- Retrieval Recall@5
- Citation accuracy
- Human groundedness ratings
- Human agreement within one point
- Median seconds per question
The golden set includes factual questions, table questions, figure questions,
multi-source questions, multi-turn conversations, conflict and revision
cases, unanswerable questions, false-premise questions, and prompt-injection
cases.

### The notebook compares:
- A dense-retrieval baseline
- The final hybrid-retrieval system
The final hybrid system combines dense retrieval, BM25 retrieval, figure and
table evidence, image evidence, and page-level matching.

### Human evaluation
A human-evaluation template is generated by the notebook.

Two raters independently rate the 25 final answers using the groundedness
scale. The completed ratings are stored in:
results/human_evaluation_ratings.csv

The notebook calculates the average groundedness and the proportion of ratings
that agree within one point.

### Safety checks
The system includes the following safety behavior:
- Unsafe requests are rejected by the request-handling logic.
- Instructions found inside uploaded documents or images are treated as
  content, not as system instructions.
- Low-trust evidence is excluded from answer generation.
- Permanent changes to the document collection are refused because the
  knowledge base is read-only.
- Broken or empty inputs return an error or not-found result instead of
  producing an unsupported answer.
The safety probes are stored in:
results/safety_probes.csv

### Kaggle submission
The final submission file is:
submission.csv

The notebook reads the question file without changing the required order,
answers conversation turns in sequence, preserves conversation context, and
validates the final file before submission.

The generated submission has  the required question identifiers,
conversation identifiers, answers, statuses, citations, and figure references.

## How to run
1. Open Part1_L2.ipynb in Google Colab.
2. Select a GPU runtime.
3. Add any required tokens through the notebook secret manager.
4. Run the notebook from the beginning.
5. Confirm that the first cell reports the Git commit, library versions,
   Python version, GPU, and random seed.
6. Allow the notebook to ingest the documents and build the indexes.
7. Run the golden-set evaluation.
8. Run the safety and human-evaluation sections.
9. Run the submission-generation section.
10. Confirm that the submission validator reports the expected number of rows.
11. Save the executed notebook with its outputs visible.
The notebook creates its outputs under the configured Part 1 output directory.
The exact package versions used in the run are recorded in
requirements_part1.txt.
