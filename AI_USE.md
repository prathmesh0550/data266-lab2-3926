## 2. Give one specific thing it produced that was wrong.

One error happened in Part 1 when the answer parser assumed that every citation returned by the vision-language model would be a string. The generated output sometimes gave a dictionary inside the citation list instead of a normal citation label. The code then tried to check that dictionary inside a set of allowed citation strings. This caused the error `TypeError: unhashable type: 'dict'`. The problem was not obvious from the answer itself because the model had still returned a JSON-like response. This showed me that valid-looking model output still needs type checking before it is used by the rest of the program.

## 3. How did you find out, and what did the failure look like?

I found the problem by adding some conversation demonstration and evaluation cells in Part 1. The failure occurred inside `parse_answer_json`, while the code was validating the citations returned by the model. Instead of producing the expected answer dictionary, the cell stopped with `TypeError: unhashable type: 'dict'`. This meant that one malformed citation could stop the entire request instead of being ignored safely. I also noticed during testing that long evaluation runs made it important to print clear progress and save intermediate results. These tests helped me distinguish between a retrieval problem, a model-output formatting problem, and a runtime problem.

## 4. What did you change, and why does your version work?

I changed the answer-processing logic so that citations and figure references are checked for the correct type before they are compared with the allowed values. Invalid entries are filtered out instead of being used directly in a set lookup. I also kept the JSON fallback behavior so that malformed model output returns a controlled `not_found` result rather than crashing the notebook. In Part 1, I added clearer handling for missing evidence, false premises, follow-up questions, temporary conversation values, and unsafe requests. I used similar checking in Parts 2 and 3 by validating generated metadata, safety results, agent statuses, and evaluation outputs before reporting them. The final version works because it treats model responses as untrusted input and validates them before using them.
